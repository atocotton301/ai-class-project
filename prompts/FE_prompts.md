💻 HanS-Plan AI: 온보딩 프로필 설정 및 데이터 파이프라인 프롬프트 기록
작업자: 조선기 (또는 본인 이름 기입)
작업 기간: 2026-05-25
구현 목표: 사용자의 기본 학적 정보와 목표 비교과 포인트를 입력받는 온보딩 UI를 구현하고, 한성대 마일리지 규정(인정/이월/소멸) 실시간 계산기 및 팀원(알고리즘 담당) 연동을 위한 JSON 데이터 저장 파이프라인 구축

1단계: 기본 폼(Form) UI 구성 및 학과별 데이터 동적 매핑
작업 의도: 초기 진입 시 유저의 학적 정보(이름, 학번, 이메일)를 받고, 선택한 학과에 따라 추천 자격증 목록이 동적으로 바뀌는 인터랙티브 UI를 구성하기 위함.

입력 프롬프트: > "한성대 비교과 스마트 내비게이터의 첫 화면인 온보딩 페이지를 만들 거야. Streamlit을 사용해서 이름, 학번, 이메일을 입력받는 폼을 만들어줘. 그리고 '데이터 사전 정의'로 8개 학과 딕셔너리를 줄 테니, 학과를 선택하면 그 학과에 맞는 추천 자격증 목록이 드롭다운으로 연동되게 코드를 짜줘."

결과: st.selectbox와 st.multiselect를 활용하여 학과 변경 시 자격증 목록이 즉각적으로 렌더링되는 동적 UI 뼈대 완성.

2단계: 실시간 비교과 포인트 시뮬레이터 및 비즈니스 로직 적용
작업 의도: 학교의 복잡한 마일리지 규정(학기당 최대 200점 인정, 200점 이월, 한도 초과 시 소멸)을 코드로 구현하고, 슬라이더 조작 시 예상 결과를 즉시 보여주어 UX(사용자 경험)를 극대화하기 위함.

입력 프롬프트:

"이번 학기 목표 포인트를 설정하는 슬라이더(최대 800점)를 추가해 줘. 그리고 학교 규정에 맞게 파이썬 로직을 짜줘. 한 학기당 인정은 최대 200점, 다음 학기 이월은 최대 200점, 400점을 초과하면 소멸돼. 이 계산 결과를 '현재까지 취득한 점수'와 합산해서 4칸짜리 메트릭(Metric) 대시보드로 직관적으로 보여주게 만들어줘."

결과: min, max 함수를 활용한 정산 로직이 적용되었으며, 슬라이더를 움직일 때마다 예상 포인트와 소멸 예정 포인트가 실시간으로 자동 계산되는 대시보드 시각화 완료.

3단계: Streamlit 폼 에러 디버깅 및 유효성 검사(Validation)
작업 의도: 폼 제출 시 발생하는 Streamlit 고질적 에러(Missing Submit Button)를 해결하고, 잘못된 데이터가 DB로 넘어가는 것을 막기 위한 예외 처리(정규식 등)를 추가하기 위함.

입력 프롬프트:

"작동은 하는데 화면에 'Missing Submit Button' 에러가 떠. form 구조랑 제출 버튼 위치가 꼬인 것 같아. 폼 제약을 없애고 실시간 인터랙션 구조로 변경해서 에러를 해결해 줘. 그리고 최종 제출 버튼을 눌렀을 때 학번이 숫자가 아니거나 7자리가 아닐 때, 이메일이 @gmail.com 형식이 아닐 때 에러 메시지를 띄우는 벨리데이션(Validation) 로직을 추가해 줘."

결과: 에러 유발 폼 구조를 제거하여 실시간 렌더링 최적화를 달성했고, 정규표현식(re 모듈)을 활용한 꼼꼼한 입력값 검증 로직 추가 완료.

4단계: 협업을 위한 데이터 파이프라인 구축 (JSON 분리 저장)
작업 의도: 자격증 데이터를 전공 특화와 공통 영역으로 분리하여 데이터의 질을 높이고, 다른 팀원이 개발할 '추천 알고리즘(recommender.py)'에서 이 데이터를 바로 꺼내 쓸 수 있도록 로컬 파일 형태로 저장하기 위함.

입력 프롬프트:

"목표 자격증을 전공 특화 자격증과 공통 자격증(토익, 컴활 등) 두 개로 UI를 분리해서 받아줘. 그리고 온보딩에서 수집한 데이터(st.session_state)를 서버 메모리에만 두지 말고, 팀원이 추천 알고리즘을 짤 때 바로 읽어서 쓸 수 있게 os와 json 라이브러리를 써서 data/user_profile.json 파일로 영구 저장해 주는 로직을 맨 밑에 추가해 줘."

결과: 팀원 간 데이터 연동을 위한 완벽한 파일 구조(data 폴더 자동 생성 및 JSON Dump)가 구축되어, 프론트엔드(UI)와 백엔드(알고리즘)의 브릿지 역할 구현 성공.
